# Le Pouliguen Live: safety, security and ergonomics audit

Date: 2026-08-17. Scope: `web/` (React 19 + Vite 8), `tools/`, `.github/workflows/`, `render.yaml`, and the live site at presquile-le-pouliguen.berteloot.org.

## Verdict

No exposed secrets, no injected user input, no auth surface, no personal data collected. Headers are live and strict, the CSP is real, and Brotli is on. The defects that matter are three: an unescaped-HTML class in the Leaflet layers, a deploy loop that rebuilds the site up to 48 times a day, and a tide card that shows a past tide every evening.

Numbers below come from requests against production: 180 KB JS, 16 KB CSS, 24 KB transit.json transferred (Brotli). The bundle is 660 KB raw JS.

## Security

### S1. Leaflet tooltips take raw HTML, and every tooltip call passes unescaped strings

Leaflet assigns string content with `innerHTML` (`leaflet-src.js:10034`, shared by Popup and Tooltip). Every `bindPopup` call in this codebase escapes its inputs. Every `bindTooltip` call does not.

| Site | Value | Origin |
|---|---|---|
| `components/ShipMap.tsx:108` | `ship.name` | AIS broadcast, relayed by aisstream/VesselAPI |
| `components/BusMap.tsx:184` | `v.routeShort`, `v.headsign` | GTFS-RT live feed |
| `components/BusMap.tsx:117` | stop `name` | GTFS static snapshot |
| `components/PoiMap.tsx:65,78` | `m.title`, `line.title` | Cap Atlantique open data (street, beach, circuit names) |

The ship name is the one that matters. An AIS vessel name is 20 characters of the ITU 6-bit alphabet, which includes `<` and `>`, and it is set by whoever operates the transmitter. `tools/build_ais_cache.mjs` only calls `.trim()` on it (line 512, 541), so the string travels intact into `offshore-ships.json`, gets committed, and is rendered. The CSP allows `'unsafe-inline'` in `script-src`, so an injected handler would run.

Also `ShipMap.tsx:37` interpolates `ship.coordinateLabel` without `esc()` while escaping every neighbour. That one is safe today because the value is built from `toFixed(4)` on two numbers, but it is the same oversight.

Fix: pass every tooltip as a DOM node. `bindTooltip(document.createTextNode(text))` takes Leaflet's `appendChild` path and ends the whole class. Or route every tooltip through the shared escaper.

### S2. `escapeHtml` guards quotes but not URL schemes

`lib/html.ts` escapes `& < > "`. That stops attribute breakout. It does not stop `javascript:`, which contains none of those characters and passes through untouched into an `href`:

- `App.tsx:903` bike-share `rentalUrl` (parsed out of Cap Atlantique's `rental_uris` JSON)
- `App.tsx:1472` beach `url` (`lien_site`)
- `App.tsx:2229` circuit `pdf` (`fiche`)

The same unvalidated URLs also reach React `href` props at `App.tsx:1488`, `2256`, `CinemaPax.tsx:77,104,107,137`, `SportsBookings.tsx:116,133,155`. React warns on `javascript:` hrefs in development but still renders them.

The padel chain is the widest: `tools/build_padel_events.mjs:44-54` regex-scrapes `href` values out of a third-party WordPress site and commits them verbatim to `padel-events.json`, which `SportsBookings.tsx` renders as links. WordPress sites get defaced; this path has no scheme check anywhere along it.

Fix: one helper, used at every boundary.

```ts
export function safeUrl(raw: string | null): string | null {
  if (!raw) return null;
  try {
    const u = new URL(raw, window.location.origin);
    return u.protocol === "https:" || u.protocol === "http:" ? u.href : null;
  } catch {
    return null;
  }
}
```

Apply it in the fetch layer (`localdata.ts`, `capatlantique.ts`, `padel.ts`, `cinema.ts`) so bad URLs never enter state, and in `build_padel_events.mjs` so they never enter the committed JSON.

### S3. Two high-severity advisories in build dependencies

`npm audit`: `brace-expansion` (GHSA-rgw5-rvv9-x895, DoS) via oxlint, `nanoid` (GHSA-2v37-7h3g-55p8) via vite/postcss. Both are transitive devDependencies, neither ships to the browser, and neither is reachable without hostile input to the build. `npm audit fix` clears both. Vite is also 8.1.5 against 8.2.1 current.

### S4. CSP hardening, two lines

Already strong. Two gaps: no `form-action` directive (add `form-action 'self'`, or `'none'` since the site has no forms), and `frame-ancestors 'self'` where `'none'` is correct for a site that never frames itself. `'unsafe-inline'` in `script-src` is required by the inline gtag bootstrap in `index.html`; a nonce would remove it, but that needs a build step Render's static hosting will not give you, so leave it.

### S5. Actions token sits on disk while third-party code runs

Every cache workflow uses `permissions: contents: write` and `actions/checkout@v4`, which leaves the `GITHUB_TOKEN` in `.git/config` by default. `padel-events-cache.yml` and `ais-cache.yml` then run `npm ci` and scrape third-party sites in that same job. A compromised transitive dependency in that install can push to `main`, and `main` auto-deploys. Set `persist-credentials: false` on the checkout in the scraping jobs and re-auth only for the commit step, or split scrape and commit into separate jobs.

No credentials are committed anywhere in the repo; secrets are all read from env in `build_ais_cache.mjs` and `build_shom_tide_cache.mjs`, and nothing logs them. `.gitignore` correctly covers `.monitor-state.json`, `dist/`, `img/`, and `.claude/settings.local.json`.

## Operations

### O1. The AIS workflow redeploys the whole site every 30 minutes

`ais-cache.yml` runs `*/30 * * * *`, commits `offshore-ships.json` to `main`, and `render.yaml` sets no `autoDeploy: false` and no `buildFilter`. So each refresh triggers a full `npm ci && npm run build` on Render. That is up to 48 builds a day, roughly 1,400 build minutes a month at a minute per build. Git history confirms the cadence: seven `Refresh AIS offshore cache` commits in the recent log.

Check your Render build minutes before anything else in this section. Then pick one: drop AIS to every 2 hours (ship positions in a bay do not need 30-minute resolution for this audience), or move the live-ish data off the build artifact so refreshing it does not require a deploy.

### O2. Cinema and padel workflows are scheduled on the same minute and neither can lose a race

Both use `17 */6 * * *`. Both commit to `main`. Neither has a `concurrency` group, and neither guards the push:

```yaml
git add web/public/data/cinema-pax.json
git commit -m "Refresh Cinema Pax cache"
git push          # no pull --rebase, no retry
```

`ais-cache.yml` already has the right pattern (pull-rebase, abort cleanly, skip the commit). Copy it into both, and give both a `concurrency` group and `timeout-minutes` (only the AIS job has a timeout today; the others can hang to the 6-hour default).

### O3. The monitor cannot report its own death

`tools/site_monitor.py` is careful work: retries, per-check retry statuses, state-based dedupe, `if: always()` on the state save. Two gaps.

The state lives only in the Actions cache. When that entry is evicted (7 days idle) or the restore misses, `previous` comes back empty and every currently-failing check re-alerts as new. The cost is a burst of duplicate Telegram messages.

The larger one: nothing watches the watcher. If `load_json` throws on a malformed config, the job goes red and no Telegram goes out. And GitHub disables scheduled workflows in a repository with no *human* activity for 60 days; bot commits do not reset that timer, so all five schedules here can stop silently. This is the failure mode in `feedback_silent_cron_produced_nothing`. Add a heartbeat: have the monitor send a "still alive" ping on a fixed day, or have Pierre alert when no monitor run has been observed in 24 hours.

### O4. Alert selectivity

Of 22 checks, roughly half watch third parties you cannot fix: Le Croisic's website, Cap Atlantique, Loire-Atlantique, the Google Translate endpoint. A Cap Atlantique outage will page you. Split the config into checks that mean "my site is down" (canonical homepage, Render origin, sitemap, manifest, the committed JSON snapshots) and checks that mean "an upstream is degraded" (everything else), and only let the first group reach Telegram. `feedback_alert_selectivity` applies here.

## Functional and ergonomic findings

### E1. The tide card shows a past tide every evening

Confirmed live at 23:26 local: the `MARÉE` essential read "Dernière haute mer 20:15, il y a 3 h". The cause sits in how the marine window is fetched, so it repeats every evening.

`App.tsx:684` calls `fetchMarineForDate(selectedDateValue)`, and `config.ts:20` builds that URL with `start_date` and `end_date` both set to the selected day. Then `applyShomTideCache` (`lib/openmeteo.ts:176,189`) filters SHOM's seven days of tide events down to `availableDays`, the day set present in the marine series. So `tideExtrema` never contains tomorrow, `nextExtremes` returns empty after the day's last extremum, and `essentialTide` falls back to `selectedDayExtrema[last]`, a tide already past.

The `essentialTideIsPast` flag and the "Dernière" wording mean this state was noticed and labelled rather than fixed. But the card is the first thing on the page and it is useless for several hours every evening, which is exactly when someone checks tomorrow's low tide.

Fix: fetch the selected day plus one, `end_date = day + 1`. SHOM's events for tomorrow then survive the `availableDays` filter and `upcoming[0]` becomes tomorrow's first tide. Note `fetchMarine()` at `openmeteo.ts:77` is dead code and already uses the wider window (`past_days=1&forecast_days=2`); the fix is close to what that constant already describes.

### E2. Hashed assets are served with `max-age=0`

Production headers on `/assets/index-DQXxEILq.js`:

```
cache-control: public, max-age=0, s-maxage=300
```

That is Render's default, and it means content-hashed immutable files get zero browser cache. Every cold session re-fetches 196 KB of JS and CSS that can never change without changing its filename. Add to `render.yaml`:

```yaml
      - path: /assets/*
        name: Cache-Control
        value: public, max-age=31536000, immutable
```

Leave the JSON under `/data/*` on a short TTL; that data does change behind a stable name.

### E3. "Découvrir" is clipped on desktop

Verified at a 1886 px viewport: the nav renders "Découvr", cut mid-word. `.app` caps at `max-width: 980px` (`App.css:49`), so the eight-link nav must fit in roughly 500 px after the brand and the language switcher. It never can. `.topnav` sets `overflow-x: auto` with `scrollbar-width: none`, so there is no visual hint that anything is hidden. The hamburger only appears below a **viewport** width of 1180 px (`App.css:3649`), while the constraint is the 980 px **container**, so the truncation happens precisely on wide screens.

The clipped item is "Découvrir", the only other page on the site. Fix any one of: raise the hamburger breakpoint above 1180 px, tighten nav gap and font at desktop, or let the nav wrap to a second row.

### E4. The English translation reads as machine word-salad in places

Verified on the live site with `?lang=en`. "La côte" becomes "The side". "Côte" in the nav becomes "Side". "Dernière haute mer" becomes "Last high seas". "Sport résa" becomes "Resa sport". Meanwhile "Qualité de l'eau" stayed French, so the page renders half-translated.

The cause is in the design: `LanguageSwitcher.tsx` translates one DOM text node at a time via `translate_a/single`, so no phrase has any context, and single words like "Côte" are unresolvable in isolation. Two consequences worth weighing:

- The endpoint is Google's undocumented internal `gtx` API. It is unauthenticated, rate-limited at Google's discretion, and its use is not covered by any terms you hold. When it starts returning 429, `translateText` throws, the `catch` swallows it, and the page silently stays French with no message to the visitor.
- A static dictionary for the roughly 200 strings of chrome (nav, card titles, labels) would translate better than the API does, cost nothing, work offline, and never rate-limit. Live data values mostly do not need translating at all. That is the fix I would pick: hand-translate the shell, drop the DOM walker.

If you keep the walker, cap the localStorage cache. `cacheKey` writes one entry per string per language and nothing ever evicts them.

### E5. The translation walker fights its own MutationObserver

`applyLanguage` observes `characterData` on `document.body` (line 290) and its own `processQueue` writes `node.nodeValue` (line 255). Assigning `nodeValue` fires a `characterData` record, `enqueue` runs again, `sourceTextForNode` returns the original (line 207), `shouldTranslateText` passes, and the node is re-queued. The translation comes from the localStorage cache so there is no second network call, but the write-observe-write cycle re-fires on the 120 ms debounce indefinitely. Add that to the `setNow(new Date())` interval at `App.tsx:667`, which re-renders the whole 2,400-line component every 30 seconds, and a phone left on this page in English burns battery doing nothing visible.

Fix: set a flag around the mutation writes, or ignore records whose target is in `translatedByNode` with a matching value.

### E6. `localStorage` at render time can white-screen the app

`App.tsx:575` calls `localStorage.getItem(STOP_STORAGE_KEY)` inside a `useState` initializer, and `1095` calls `setItem` with no guard. On iOS with "Block All Cookies", or in some locked-down enterprise profiles, both throw `SecurityError`. Thrown from a state initializer with no error boundary anywhere in the tree, that renders nothing at all. `LanguageSwitcher` already wraps its storage access in `try/catch` (lines 33, 89, 110, 130); App should do the same, and `main.tsx` should mount an error boundary so any render throw degrades to a message rather than a blank page.

### E7. No request has a timeout

None of the ~15 `fetch` calls uses `AbortSignal.timeout`. A third-party endpoint that accepts the connection and then stalls leaves its panel on "Chargement…" forever, with no error and no retry. Several handlers also swallow failures into empty state (`App.tsx:712-722`, `.catch(() => {})`), so a dead upstream is indistinguishable from "no data today". `AbortSignal.timeout(8000)` on each fetch, plus a distinct "indisponible" state, fixes both.

### E8. Smaller items

- **PWA without a service worker.** `manifest.webmanifest` makes the site installable, and the CSP already allows `worker-src 'self' blob:`, but there is no service worker. For a site people open on the seafront with two bars of signal, caching the shell and the last-known data payloads is the single biggest perceived-speed win available.
- **French aria-labels are unaccented.** "Jour precedent" (`DateSelector.tsx:29`), "Date consultee" (line 23), "Courbe de maree sur la journee" (`TideChart.tsx:59`). French screen readers mispronounce them. Free fix.
- **`role="tablist"` with no panels.** `App.tsx:2011` and the ship/circuit filters announce as tabs but control no `tabpanel`. `role="group"` with `aria-pressed` on the buttons describes what these actually are.
- **No skip link.** Eight nav links plus a language switcher precede the content on a very long page.
- **`body { overflow-x: hidden }`** (`App.css:45`) suppresses the symptom of any horizontal overflow, which is how E3 stayed invisible.
- **Code splitting.** The single 660 KB bundle includes Leaflet and `gtfs-realtime-bindings`/protobufjs, none of which the first paint needs. 180 KB over the wire is fine; the parse and execute cost on a low-end phone is not. `React.lazy` on the four map components and a dynamic import for the protobuf decoder would cut first-load work substantially.
- **`decodeHtml` can crash the padel scraper.** `build_padel_events.mjs:18` calls `String.fromCodePoint(Number(code))` on any numeric entity; an out-of-range value throws `RangeError` and fails the workflow. Clamp it.

## What is already right

Worth recording so it does not get traded away in a refactor: every popup escapes its inputs; ODS queries interpolate only hardcoded constants, never user input; geolocation is user-triggered from a button rather than requested on load; secrets live only in env and Actions secrets; GA skips localhost and the Render preview URL; the noscript block is real content; `newTabProps` adds `rel="noopener noreferrer"` on every external link; touch targets are 44 px; `prefers-reduced-motion` and `:focus-visible` are handled; the closed mobile nav is `display: none` so it holds no hidden focus targets; and the monitor's retry and dedupe logic is better than most production monitors.

### Where the header records actually live

Applied through the Render API on 2026-08-18 with Stan's go-ahead, after the file
change alone turned out to do nothing.

This service does not sync its configuration from the blueprint. Its headers are
individual service records under `/v1/services/{id}/headers`, and
`serviceDetails.headers` is `null`, so the `headers:` block in `render.yaml` had
been correct and inert all along. The fix was a `PUT` of the full six-record set:
the five existing records with the CSP amended, plus a `Cache-Control` record
scoped to `/assets/*`. The `PUT` replaces the whole set: the response carried six
fresh ids, and a follow-up read confirmed a single CSP record. No redeploy was
needed.

Verified on fresh origin responses rather than the edge: `frame-ancestors 'none'`
and `form-action 'none'` are being sent, `/assets/*` returns
`max-age=31536000, immutable`, `/data/transit.json` still returns the short TTL,
and all five original security headers are intact. The previous records are saved
in case a rollback is ever wanted.

The drift risk remains: `render.yaml` documents intent while the dashboard holds
the truth, and nothing keeps the two in step. Linking the service to the
blueprint would make the file authoritative.

Deliberately not done:

- **E4, the translation approach.** Still sends one text node at a time to Google's `gtx` endpoint, and "La côte" still becomes "The side". Replacing it with a hand-written dictionary is a product decision and a day's work, so it stays yours to call.
- **S5, `persist-credentials: false` on the scraping workflows.** The push path cannot be exercised without a live cache change, and a wrong guess there stops the caches silently. Worth doing in a window where you can watch a run.
- **E8's service worker and code splitting.** Both are new work rather than repairs. The 500 kB chunk warning in the build output is the code-splitting one.
